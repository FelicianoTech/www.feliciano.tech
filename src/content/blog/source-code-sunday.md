Each year the leaves fall and Starbucks cups gain a splash of color.
That's when I know Thanksgiving is coming.
With that comes a review of my past year and the people in my life that I am thankful for.
Most years I not only think about personal people but the open-source projects I use and the people who help build them.
I'd like to encourage others to join me in thanking these people on the Sunday after Thanksgiving, which I am dubbing Source Code Sunday.

<!--more-->

## Source Code Sunday

A day in November for users of open-source software to share their appreciation to maintainers of that software.
This will be the Sunday after Thanksgiving (U.S.) a.k.a. the last Sunday of November.
We have Black Friday, Small Business Saturday, Cyber Monday, and Giving Tuesday(?).
I figured Sunday could be something nice for us tech people.

The name is a misnomer though.
While the name points to software, I really want to focus on the people creating the software.
The problem is, alliteration is huge when it comes to helping people remember things, thus I landed on Source Code Sunday.
Have a better name idea? Let me know.

## Participating

Now, what's the best way to go about doing this?

Well, the most straightforward approach would be via a GitHub (or GitLab) Issue.
Before you open a new one, check if one exists.
Basically, open up an issue and thank the lead maintainer, maybe other maintainers that are around, frequent contributors, whomever your heart feels the urge to thank.

However, a GitHub Issue would be my last option.
Some projects may require issues to be opened only for code related reasons.
If a project has a forum, GitHub Discussions, social media accounts, or *shudder* a Discord, those would be great places to show your appreciation without clogging up the engineering backlog in GitHub Issues.

### Two things not to forget

1. Let's not forget that people contribute with code but also: project management, graphics, copy editing, organizing, etc.
1. This may be controversial to some, but let's thanks the businesses (and employees) that run open-source projects as well. In many companies, justifying that a codebase be open-sourced, and for it to stay that way, can take a lot of internal campaigning and politics. Publicly acknowledging the companies that put in the effort can go a long way.

## Related Works

If this sounds interesting to you, there are other preexisting "campaigns" around code and maintainers that you might also want to participate in.

* [Maintainer Month](https://maintainermonth.github.com/) \- A month for open source maintainers to gather, share, and be celebrated. This is a project by GitHub and is run in May.  
* [Hacktoberfest](https://hacktoberfest.com/) \- A month-long celebration of all things open source. This is a project by DigitalOcean and Major League Hacking (MLH) and run in October.  
* [24 Pull Requests'](https://24pullrequests.com/) \- Giving back to open-source for the holiday. This is a standalone project and run in December.
